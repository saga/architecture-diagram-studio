# diagram-design 风格与布局实施评估及计划

> **历史研究与候选需求（非当前实施清单）。** ADR-0011 移除了 `DiagramDocument` 和依赖它的自定义布局/质量实现；本计划保留的是视觉、几何与可访问性原则，不是可直接迁移的代码。复用边界由 [ADR-0012](./adr/0012-native-diagram-extension-contracts.md) 定义：未来布局/样式能力通过 `NativeDiagramOperationProvider` 产生类型化原生操作，质量/可访问性通过 `NativeDiagramAnalysisProvider` 产生诊断。当前只有这些接口，没有已注册的布局或质量 provider。

## 结论

采用 diagram-design 的几何约束、布局质量门、连接器语法、视觉 token 和可访问性原则；不替换现有 ELK/Dagre，不复制其 HTML 输出，也不把示例图的复杂度上限作为通用硬限制。

本文的模块名、测试名和阶段状态属于旧实现。当前 V2 基线是完整原生 XML、`native-edit-operations.ts` 和原生 Draw.io bridge；不能引用本计划里的已删除函数作为当前 API。未来实现应通过 `src/model/native-diagram-capabilities.ts` 定义的接口接入，并复用统一 XML schema、操作验证、revision 检查和 editor acknowledgement。

## 评估结论

| 能力 | 判断 | 实施决定 |
|---|---|---|
| 几何质量门与冲突定位 | 高价值，已有基础 | 扩展指标和诊断；严重错误与软评分分开 |
| 4px 网格 | 高价值 | 统一自动布局、拖动吸附和 Draw.io 网格；不强制重写手工尺寸 |
| 文本溢出与 CJK 宽度 | 高价值 | 用统一的字符宽度估算检测标题、技术信息、描述和边标签 |
| 端口分散与连线避障 | 高价值但较复杂 | 先做共享端口分配和正交路径避障，交叉桥接暂不作为通用前置条件 |
| 视觉 token / 对比度 | 高价值 | 保留现有配色，补充可测量的对比度审计与风格一致性 |
| 语义布局和 containment | 有价值，依赖数据模型 | 复用现有 `preferredSide`、`preferredRank`、`boundaries` 等字段，分阶段增强 |
| 时序图 fragment | 部分已实现 | 保留现有模型和导出；校验范围、间距及边界 |
| 复杂度预算 | 适合提示，不适合硬限制 | 输出质量警告和拆图建议，不拒绝正常的大型图 |
| 原生编辑器可访问性 | 高价值 | 检查 iframe 标题、键盘操作、属性面板字段标签和焦点行为 |

不在本轮实现 45 种图表类型、全局固定节点尺寸档位、所有交叉必然使用 hop/bridge，或替换布局引擎。这些要么超出 Studio 当前核心范围，要么会损害用户手工布局和复杂工程图的合法性。

## M1 — 质量检测与诊断

- 扩展质量指标：网格偏移、文本溢出、边标签越界、路由问题、端口间距、对比度与中文宽度问题。
- 修正时序图质量检测使用的路径几何，使其复用 canonical `sequenceMessageGeometry`，避免检查路径与显示路径分歧。
- 明确严重几何约束优先于总分；候选布局先比较硬错误，再比较软指标。
- 为每一类新规则增加可定位的 `QualityIssue` 和回归测试。

验收：重叠、连线穿过非端点节点等问题可定位；时序消息检测与实际几何一致；严重错误不会被其他指标的得分抵消。

## M2 — 4px 网格与文本布局

- 将拖动吸附与 Draw.io 网格统一为 4px；自动布局对非锁定节点执行网格吸附后重新路由并检查冲突。
- 保留导入/手工设置的节点宽高，不强制套用有限尺寸档位。
- 引入 Unicode-aware 的文字宽度估算，覆盖中日韩全角字、组合字符、拉丁字符和常见标点。
- 检查节点标题、技术名称、描述及边标签的容纳空间与画布边界。

验收：坐标、画布吸附和导出网格一致；中英文混排及长标签问题会被检测，且不会因尺寸取整引入重叠。

## M3 — 端口分配与路径避障

- 按端口所在边，为多条入/出连接分配不同 attach point。
- 在端口间距不足时产生明确诊断；正交路径优先避开非端点节点。
- 保持显式 `points` 的语义和现有 polyline/curved 设置；不将正交强制应用于时序图。
- 将复杂交叉桥接列为有独立几何规则和可视回归样例的后续优化，而不是用视觉桥接掩盖错误路由。

验收：同一节点同一边上的多条线不再全部使用同一个端口；自动路由不穿过无关节点；路径变化后执行质量复查。

## M4 — 风格 token 与对比度

- 复用现有语义角色颜色，加入 WCAG 对比度计算和质量报告。
- 核查节点文字/填充、描边/画布、连线/画布和边标签组合；低对比度以警告呈现。
- 统一画布和 Draw.io 导出的网格/文本基础规则，避免新建平行风格系统。
- 不以“单一 accent”规则强行重绘所有语义颜色。

验收：对比度检查可单测、可回归；画布 token 的变更能够在质量报告中反映，且不修改图语义。

## M5 — 语义布局与时序图

- 让 external、storage、preferredSide 和 preferredRank 的约束在各布局引擎及后处理后保持一致。
- 复用现有 boundary 模型，为包围范围、标签空间和成员节点关系增加一致性检查。
- 校验时序图 fragment 的参与者范围、有效消息区间和边界间距；复用现有 sequence 模型与导出能力。
- containment 若需要独立父子层级语义，则在已有 boundary 上增量扩展，避免先引入另一套平行模型。

验收：语义方向约束可预测；边界包围成员且不会遮挡内容；时序 fragment 经编辑、布局、导出后保持一致。

## M6 — 复杂度提示与可访问性

- 按图类型输出复杂度警告（例如时序生命线/消息数、一般图的节点/边数），不把建议上限变成服务端硬限制。
- 检查原生 Draw.io iframe 的可访问名称、键盘操作和属性面板控件标签；不再为已移除的 SVG 画布设计无效需求。
- 给复杂度规则和可访问性属性增加测试；保持现有键盘选择行为。

验收：超出风格预算时返回建议，而不是拒绝保存；辅助技术能识别图表名称、节点名称和关系标签。

## 实施与回归策略

1. 每阶段都要补对应单测，禁止只改评分而没有几何样例。
2. 优先检查硬约束：语义有效性、节点重叠、连线穿节点、越界；再优化交叉、标签、对齐、留白和复杂度。
3. 每次重新路由后重新评估质量，避免局部修复制造新问题。
4. 保持原生 Draw.io 为唯一画布。不直接搬入 ELK/Dagre 或 SVG 渲染实现；未来布局能力须针对原生 mxCell 输出类型化操作，不得重建整份 XML。
5. 最终以 V2 typecheck、单元测试和生产构建结果作为交付门槛。

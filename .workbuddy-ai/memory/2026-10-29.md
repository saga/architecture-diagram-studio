# 2026-10-29

## 布局状态栏文案未进 traces（已修复）

现象：画布状态栏显示 `Auto layout · 23/23 nodes, 0/0 connectors · no connectors, arrangement kept ·
warning: 18 contained node(s) remain ungrouped`，但 Agent traces 里搜不到这些文字。

根因（三层）：
1. 那句话只在 `App.tsx` 里拼给 `setLastAction`（React state），从未传给 `recordDiagnostic`；
   trace 只存了 29 个裸计数器（`coverage`），所以文本搜索 0 命中，刷新即丢。
2. `drawio.layout.ui.requested` / `.ui.serialized` 都用默认 `info` 级别。UI 自称 "warning"，
   日志却是 info，于是「Warnings / errors」过滤器看不到、导航错误点不亮。
3. `drawio.layout.ui.failed` 的 details 不带 coverage，布局抛错时那 18 个节点彻底查不到；
   且 `native-layout.ts:879` 把 `unownedContainedVertexCellIds` 折成 `.length`，只剩数字没有 ID。

改动：
- `native-layout.ts`：`NativePageProjection` 增加 `spatialRegionUnownedContainedVertexCellIds: string[]`；
  `NativeLayoutPlan` 增加 `unownedContainedVertexCellIds: string[]`（coverage 形状**未变**，
  避免破坏 `native-layout.test.ts` 里 coverage 的 `toEqual`）。
- `App.tsx`：summary 提成 `layoutSummary` 变量，同时给 `setLastAction` 和
  `.ui.serialized` 的 message（= trace 卡片标题）+ `details.summary`；
  新增 `drawio.layout.containment.unowned`（`level: "warn"`，带前 20 个 cell ID）；
  `.ui.failed` 带上 `plannedCoverage` 和 ID（在 try 外声明，失败也能记录计划内容）。

验证：`tsc` 干净；layout+components+server 289 项全过；全量 478/479，唯一失败是既有的
msagl 满并发超时（单文件跑 84/84 通过）。真实快照 `jrXY4hO8n29qiqvIHeQG` 上
`unowned=18, ids=18`，前 5 个 ID 与截图中的散落便签对应。

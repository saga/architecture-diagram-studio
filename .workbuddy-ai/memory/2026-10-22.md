## Agent trace 页重构（18:14）

用户四点要求：四个卡片有什么用 / 去掉非 copilot 的无聊事件 / 两行信息变一样 / 展开箭头放最后。

### 四个卡片是什么

`trace-metrics` 只是四个计数：总数、含 "copilot" 的事件数、含 "layout" 的事件数、error 数。
和下面 filter chips 完全重复，且 `copilotCount` 用 `event.includes("copilot")` 子串匹配，口径不准。
**已删除**（连同 CSS 与暗色主题里的引用）。

### "两行信息变一样"的真因

不是视觉问题，是数据问题：`/api/workspace/logs` 把 **agent 审计日志**（`copilot-server.ts:1139-1148`）
映射成 trace entry 时，`message: typeof event === "string" ? event : "Copilot agent event"` ——
**message 直接等于 event id**。于是 `models.empty` 那行第一行是 `models.empty`、第二行还是 `models.empty`。
实测服务端 1200 条里 1075 条是这种"裸日志"。

### 处理方式

- `isLowLevelTrace()`：warn/error 一律保留；否则 `message === event`（服务端裸日志）、
  或在 `LOW_LEVEL_EVENTS`、或命中 `LOW_LEVEL_EVENT_PREFIXES`
  （`drawio.message.` / `drawio.bundle.check.` / `drawio.handshake.` / `ui.theme.`）→ 归为 low-level。
- 工具栏右侧 `Show low-level events · N` 开关，默认关。**实测 1200 → 125 行。**
  README 和设置页里"看 drawio.handshake.*"的排障指引都补了"先打开这个开关"。
- `traceTitle()`：message 等于 event 时，从 details 里取 `errorMessage/error/note/reason/message` 当标题。
  于是 `turn.failed` 那行现在显示 "You have exceeded your monthly quota (Request ID: …)"，event id 退到 meta。

### 行布局

原来三行（head / message / antd Collapse 的 "Request prompt / response / event details"）。
现在一行：level 徽标 + message（主，ellipsis）+ event id（meta）+ 时间 + 行尾 `›` 按钮。
丢掉 antd `Collapse`，改成 `expandedTraceId` 单开 + 自绘 details，箭头 `rotate(90deg)` 表示展开。
`.trace-entry-head` 系列 CSS 全部换成 `.trace-entry-row`；`.trace-entry` padding 18/19 → 11。

### 坑

- `.trace-toolbar` 在全局（非 media query）被设成 `flex-direction: column; align-items: stretch`，
  新加的开关按钮会被拉成整行居中。改成 `flex-wrap: wrap` + `.trace-noise-toggle { margin-left: auto }`。
- 截图验证时机器上**已经有用户在跑的 copilot-server（4175）**，所以 `/api/workspace/logs` 能返回 1200 条真实数据，
  正好拿来验证过滤比例；用 `channel: "chrome"` 起 playwright（ms-playwright 缓存是空的）。

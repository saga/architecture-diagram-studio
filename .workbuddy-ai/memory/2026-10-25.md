## Draw.io 文档背景/网格在 Studio 中被主题色盖掉（只分析，未改）

- 现象：文件 `background="light-dark(#FFFF66,#121212)"` + `grid="1"`，Studio 里显示为主题 canvas 色且无网格。
- 结论：XML 未损坏（磁盘文件里属性都在）；是 `src/model/drawio-theme.ts:73-75` 注入 iframe 的
  `body, #geDiagramContainer, .geDiagramContainer, .geDiagramContainer svg { background-color: X !important }`
  在 diagram SVG 上盖了一层不透明底色，把 drawio 画在下一层的页面背景（`.geBackgroundPage` 的内联色）
  和网格图（同一元素的内联 background-image）都挡住了。
- 证据：注入 `#studio-native-theme` 时 `.geBackgroundPage` 计算值仍是 rgb(255,255,102)（说明 drawio 正确应用了
  文档背景），但可见画布是主题色；仅移除该 style 元素 → 黄色 + 网格立刻恢复（A/B 截图）。
- 排查手法：Playwright(channel=chrome) 打开 5174 真实 app，用 frame.evaluate 读 iframe 计算样式；
  用 `page.route` 拦掉所有 `/api/workspace/**` 写请求，避免污染用户工作区。
- 修复方向（未实施）：不要给容器/svg 打不透明底色；只给 iframe body（页面外留白）上色，或让
  `.geDiagramContainer svg` 保持 transparent，让 drawio 自己的页面背景透出来。

- 该分析已落盘为 `DRAWIO-BACKGROUND-OVERRIDE-ANALYSIS-2026-10-25.md`（仓库根目录），含分层图、
  运行时计算样式证据、A/B 截图说明、影响面、三种修复方向与回归清单、复现脚本。

## Undo/Redo 一致性缺口（只分析，未改）

- 落盘为 `UNDO-REDO-GAP-ANALYSIS-2026-10-25.md`（仓库根目录）。
- 关键事实（已逐行核实，可复用）：
  - app 级 undo 由 `7933787` 删除（`historyRef` 50 条快照 + `undoDocument/redoDocument`）。
  - 原生 undo 入栈条件**只看是否在 `beginUpdate/endUpdate` 内写 model**，与是否走 draw.io UI 命令无关
    （`mxGraphModel.js:1989-2019` → `Editor.js:1652-1670`）。所以 plugin 的 `editCell`、
    `applyNativeLayoutPlan`、Copilot batch 全部可 Ctrl+Z。
  - 唯一"内容级但非模型级"的操作是 theme preset（`App.tsx:591` → `drawio-theme.ts` XML 重写
    → `setNativeXmlOverride` → `action:"load"` → `loadEmbedded` 里 `undoManager.clear()`）。
  - 宿主 `src/` 无任何 keydown 处理 → 焦点不在 iframe 时 Cmd+Z 完全无响应（比"不进栈"更基础）。
  - 宿主可代理原生 undo：`{action:"invokeAction", actionName:"undo"}`（`diagramly/EditorUi.js:27688`，
    action 注册在 `grapheditor/Actions.js:147`）；但 `invokeAction` 不检查 `isEnabled()`，需自维护状态。
  - 自动布局是现成范本：宿主算 plan → 插件单事务执行 → `action:"export"` 回传 XML 走既有保存链。
  - `DrawioFrame.tsx:687` 的 `lastSent = data.xml` 回声抑制是"drawio 编辑不触发 reload"的关键，勿破坏。
- 建议：不重建 app 级快照栈，而是 ①宿主快捷键代理 ②theme 改模型事务（先只对当前页）③不可模型化的操作给显式反操作。
